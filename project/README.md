## 2. Структура проекта

Проект организован в следующей структуре:

- `requirements.txt` – зависимости проекта (библиотеки Python, необходимые для запуска).
- `report.md` – отчёт по проекту (постановка задачи, данные, эксперименты, результаты).
- `self-checklist.md` – чеклист самопроверки проекта перед сдачей.
- `notebooks/` – экспериментальные ноутбуки:
  - EDA, прототипы моделей, отдельные эксперименты.
- `src/` – основной код проекта:
  - модули для работы с данными;
  - обучение моделей;
  - запуск сервиса/скриптов.
- `data/` – демонстрационные/учебные данные:
  - **только открытые, синтетические или обезличенные данные;**
  - при необходимости – небольшие выборки для быстрого запуска.
- `configs/` – конфигурационные файлы:
  - `.yaml`, `.json`, `.env.example` и т.п.
- `tests/` – тесты (юнит-тесты, простые проверки).
- `artifacts/` – сохранённые модели, отчёты, результаты экспериментов.

## 3. Требования и установка

### 3.1. Требования

- Python `>= 3.10` 
- Docker

### 3.2. Установка окружения

```bash

cd project
python -m venv .venv

# Активировать окружение:
# Windows:
.venv\Scripts\activate
# Linux / macOS:
source .venv/bin/activate

# Установить зависимости
pip install --upgrade pip
pip install -r requirements.txt
```

## 4. Как запустить проект

### 4.1. Загрузка и обработка данных

```bash
cd project
.venv\Scripts\activate    
python -m src.prepare         
```

### 4.2. Запуск обучения модели

```bash
cd project
.venv\Scripts\activate
python -m src.train
```

### 4.2. Запуск сервиса (API)

```bash
cd project
.venv\Scripts\activate
python -m src.api_predict
```

Или, если используется Docker:

```bash
cd project
docker build -t aie-project .
docker run -p 8000:8000 aie-project
```

Сервис запускается на порту 8000

Основные эндпоинты:
- /	GET	- Информация о сервисе
- /health	GET	- Проверка состояния сервиса
- /predict	POST -	Получение предсказаниям
- /docs	GET	- Swagger UI документация

Работоспособность сервиса можно протестировать с помощью браузера:
- get - http://localhost:8000/
- health - http://localhost:8000/health
- post - http://localhost:8000/docs вкладка predict
- docs - http://localhost:8000/docs

## 6. Тесты (если есть)

- test_health_endpoint - Интеграционный

Запрос к /health для проверки готовности сервиса
Статус 200, ответ содержит {"status": "ok", "model_loaded": ...}

- test_predict_endpoint_missing_fields - Интеграционный

Отправка запроса с неполным набором полей
Статус 200 (если модель устойчива) или 400/422 (валидация) — корректная обработка ошибки

- test_predict_endpoint_invalid_stops - Интеграционный

Отправка невалидного значения в категориальном поле stops
Статус 400/422 (валидация) или 500 (если ошибка не перехвачена) — система не падает молча

- test_clean_data_removes_outliers - Модульный 

Проверка фильтрации выбросов по признаку длительность перелета

## 8. Ограничения и дальнейшая работа

На данный момент реализован базовый функционал сервиса для предсказания цены по фиксированному набору параметров.
Текущие ограничения:
- Только один алгоритм предсказания
- Нет валидации входных данных и обработки ошибок
- Отсутствует кэширование — каждый запрос вызывает пересчёт
- Модель и данные обновляются только при перезапуске контейнера

Направления развития:
- добавить поддержку нескольких алгоритмов с выбором через конфиг
- расширить тесты до полного покрытия
- усовершенствовать проект структурно
- продумать более аккуратное логгирование
